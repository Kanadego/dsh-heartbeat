两个新功能（**心事匣**、**摘抄本**）+ 第二次全量代码审查（22 项主发现 + 一节低优先级观察）的修复与结构整改。

审查报告与逐条实验证据见 [CODE-REVIEW-2026-10-17.md](../../CODE-REVIEW-2026-10-17.md)。

## 心事匣：跳与跳之间的那道缝

心跳以前每一拍都是「重新认识自己一遍」——上一拍想到一半的事、咽回去的那句话，没有地方放。这一版给它一格便签。

**它是一格，不是队列。** 新念头盖旧念头，由每拍主动决定：想留就照原样再写一遍，想说新的才换掉。存储恒定，不随拍数增长；一条心事连着好几拍都没被盖掉，这件事本身就是它一直被想起的证据。

**投递素材包里带上它。** 引擎室的反刍备料包里没有这块——只有投递给目标会话的素材包会附带三行：

```
(你上跳留下的心事:那句没说完的话)
(留于3 跳前,已搁 2 小时 15 分,期间被叫醒过 1 次;还惦记就调 notepad 照原样再写一遍,想换新的直接写,什么都不做它下一跳就没了)
(照原样再写一遍算保留,它的年龄不会重算)
```

**生命周期靠两个序号判定，不靠时间戳**——时间戳会被新消息重置，算不出「搁了几拍」：

- 放掉的条件是「**被读过的那一拍，比最后一次触碰还晚**」（严格大于）。本拍才写下或才保留的便签从没被读过，不能被刚送出它的那次投递吃掉；
- **启动那一拍不加序号、也不丢东西**。DSH 每次启动都会先跑一拍，如果它算数，「搁了几拍」会被重启污染；
- 同文本再写一遍 = **保留**（`leftAt` / 留于第几拍 / 被叫醒的起点原样留着，只记「这拍碰过它」）；写别的文本 = 换新的，年龄从头算。

**注册成一个模型工具** `notepad`（`write` / `read` / `clear`），走和账本工具同一条路：注册在插件根上下文 → 落在全局工具层，日常会话里的 agent 看得见；引擎室被自己的预设遮住，看不到。

数据落 `data/notepad.json`（**加密**，和别的敏感文件同一套）。读写出错只记一条 `notepad_read_failed` / `notepad_write_failed` 留痕，绝不让一格便签把整拍弄挂。

## 摘抄本：她自己的笔记本

心事匣管的是「这句话要带到下一拍」，账本管的是「这件事要做」。剩下一类东西一直没有地方放：**看见就想留下来的句子**——不为做什么，只是喜欢。这一版给她一本摘抄本。

**它是一本，不是缓存。** 只增不减，除非她主动抹掉；没有状态、不会过期、不参与任何判定，写进去就是留着。

**明文落盘**（`data/excerpts.md`）。敏感数据默认加密，这本和账本一样走明文，理由也是同一个：**一本谁也翻不开的笔记本不叫笔记本**（明文里当然还有游标、计数、日志——但那是机器状态，没有人要读）。设置卡里加了「一键打开摘抄本」，她抄下的那句你随时能翻、也能自己添两行；认不出的行在改写时原样留着，手编不会把她的东西弄乱。

**注册成一个模型工具** `excerpt`（`add` / `list` / `remove`），和账本、心事匣同一条路：注册在插件根上下文 → 落在全局工具层，日常会话里的 agent 想到什么就当场抄下，不用谁下命令；引擎室被自己的预设遮住，看不到。

三本东西的分工也写进了工具说明，免得她自己拿错：

| 本子 | 记什么 | 结局 |
| --- | --- | --- |
| 账本 `data/ledger.md`（明文） | 待办与承诺，你和 agent 共享 | 做完勾掉，条目仍留在文件里 |
| 心事匣 `data/notepad.json`（加密） | 留给下一拍自己的一句引子 | 一格，会被覆盖；不保留就下一拍清掉 |
| 摘抄本 `data/excerpts.md`（明文） | 想长期留着的句子和小事 | 只增不减，除非她主动抹掉 |

## 加密换代：AES-256-GCM + DPAPI 保管的数据密钥

数据文件以前逐个交给 PowerShell 调 DPAPI 加解密——每读写一个文件就起一次进程，单次最长等 30 秒；全量测试里有 97 秒花在这上面。

现在：数据用 **AES-256-GCM** 整文件加密（含认证，改一个字节就解不开），数据密钥由 Windows DPAPI（CurrentUser）保管在 `data/vault.key`，进程启动解一次、之后不再走 PowerShell。旧版 1.x 的 DPAPI 容器（`KHBV1`）照旧能读，新写的一律是 `KHBV2`：

- 旧数据不会变成死数据——读路径两代都认；
- 旧容器平时就会自己换代：任何一次写入都落成新格式，每一跳的维护相再顺带换掉长期没动过的一个；`vault status` 报告各代数量，`vault upgrade` 一次全换；
- `vault.key` 存在但解不开时**直接报错，绝不另生成一把**（否则盘上旧数据全成垃圾）；
- 加密文件解密失败时抛错而不是返回「空」——避免调用方把 `null` 当空库覆盖掉真实数据。

> ⚠️ **回退警告**：`KHBV2` 只有 2.0 及以后认识。升级之后不要再退回 1.x；要退回就趁早——跑过 `vault upgrade`、或让数据写过一轮之后，就回不去了。

副产物：全量测试从 97 秒降到 12 秒。

## 遗忘与销毁的边界

`profile wipe` 以前只删 `profile.json` / `profile_inbox.jsonl` / `profile_journal.jsonl`，而画像的 journal 快照、归档分片、迁移备份都还在盘上——下一次重放会把画像原样长回来，用户以为「清掉了」。

- `wipe` 现在是真遗忘：live 三个文件 + 快照 + 归档分片 + 迁移备份与导入暂存残留一起删（仍不动设定、账本、周报、日志）；
- `burn` 的清单补上了迁移备份族（`*.bak-migrate-<时间戳>`）与导入暂存残留（`*.incoming-<时间戳>`），任意子目录层级都认。

## 迁移：整包全或无

导入迁移包时，以前会跳过不合格的文件、把其余部分导进去，结果可能是半个数据库。现在：

- 只有白名单里的名字能落地（`ledger.md`、画像与 journal 归档、`weekly/*.json` 等），路径越界或名字不在名单上的直接判整包失败；
- 单个容器有预算上限（**5000 个文件 / 64MB**），超了在解密前就拒绝；
- 暂存阶段只要有一个文件被拒，**整包不导入**，已暂存的一并清掉，本地数据原样不动；
- RPC 侧不再把带 `error` 的结果当成功返回。

## 记忆的正确性：流水事件化 + 证据由代码生成

画像的 journal 以前记的是「模型这一轮给的操作」，重放时用一套更宽松的规则重新解读——于是重启前后的画像可能不一样，老化（易变条目到期、低活跃标记）也从不入流水，快照会把偏差固化。

现在 journal 记的是「**规范化之后的最终事实**」：

- 每轮记录本轮写入/变更条目的完整终态，重放就是按 id 原样回放——实时路径与重放路径**完全一致**，老化也成为可重放的事件；
- 旧的 v1 流水照旧能读，新旧混在同一个文件里也逐行判定；
- 读不出来的坏行被计数暴露（`badRecords`），不再静默跳过。

**证据由代码生成**：模型只能引用本批次观察的编号（`o1`、`o2`…），引用位置、时间、来源种类（chat / screen / browse / hand / ledger）一律由代码填。此前模型可以自造引用、或自称来源是「手写」，把一条新记忆直接钉到信心上限 1.0。

其余记忆层修复：

- **观察不再丢**（合并期间到达的观察）：一轮合并只清掉它真正读过的观察，不再整文件清空；
- **跨进程锁失败关闭**：等不到锁就跳过这次写入并留痕 `inbox_locked`，不再「等 3 秒没等到就照写」；陈旧锁要同时满足「够老」与「持有进程确实不在了」才被回收；
- **被拒的更新不再改正文**：信心升级校验失败时不再留下已经写进去的新正文。

## 执行取消链

超时以前只是「不再等待」——原任务继续跑、继续写盘；看门狗到点只清了「正在跳」的标记，旧的阶段仍在后面兑现。

现在 AbortController 贯穿每一跳的所有阶段：模型调用、PowerShell 探测、视觉识别子进程、投递前的复查都接同一条取消链；超时、看门狗与插件卸载会真正取消它们，审计留 `beat_aborted`（带阶段与原因）。

## 画面与投递

- **画面不认旧图**：本跳没截到图（采集失败）时，取消本跳的画面资格并**烧掉盘上旧图**。新增 `screen.capture` 印章（只存本跳时间戳），印章、`screen.json` 与截图三者对得上才解密使用——以前只要文件在就解密，可能把上一跳的画面当成现在的；
- **投递按说话时刻记账**：写入前完整复查（静默时段、每日上限、冷却、忙窗、是否正在打字），复查条件变化也不再影响账——话已经在对方那里了，拒绝只说明条件变了，绝不表示「她没说话」。

## RPC 通道失败关闭

浏览器数据通道的鉴权依赖宿主提供的闸门。宿主没提供时，以前只拒 6 个破坏性端点，等于把画像摘要、分区、素材池、周报正文、迁移导出全向 loopback 敞开。

现在整个通道失败关闭：只放行 `status` / `config.get` / `sessions.list` / `bindings.get` / `weekly.list` 五个低敏只读端点，其余拒绝并留痕 `rpc_host_gate_missing`；端点表改为无原型对象，`constructor`、`__proto__`、`toString` 这类名字不再能穿透。

## 引擎室的工具面：复用路径漏网（已修）

引擎室的工具面靠一条白名单收窄：闲逛相唯一需要的 `web_search`，加上装了 [billion-context](https://github.com/ranxianglei/billion-context) 这类插件时的压缩三件套。这条白名单原先只在插件**自己拉起** agent 时钉（`setup` 钩子），而 `ensureAgent` 还有第三条获取路径——取到**已存在且活着**的 agent（`agent_reuse_live`，会话正开着时就走这条）——那条路径不跑 `setup`，于是插件重启后的每一跳都带着**全局层全量**在跑。2026-10-17 实测：模型看到的是 62 个工具（shell、邮件、撤销、qqbot 全在里面），而不是应有的 9 个，那一跳的决策轮还因此撞了 240 秒超时。

修法是把白名单那段抽成 `pinEngineRoomTools(deps, agentCtx, notes)`，复用分支也调一次——宿主 agent 对象本身带 `agent.ctx`，不需要重建 agent。结果写进同一行 `tool_policy`，前缀 `reuse`。 当日 22:05 实测撞上这条路径并确认：`agent_reuse_live` 那一跳写出 `reuse restrict=ok`，同跳送给模型的工具面正好是 9 个（此前同类场景是 62 个）。

## 节律配置：重启不再被默认值掀掉

`timeInjectMin` / `statusbar` / `idleMode` / `tokenSaver` 这四个字段原先在 plugin 配置 schema 里带默认值（`statusbar` 是 `false`）。问题在于启动顺序：插件先读 `ui.json`（卡片写的），随后 `applySettingsOverrides` 又拿**解析后的配置**盖了一遍——而带默认值的配置永远有值，分不出「用户明确设成 false」和「用户没设」。于是每次重载，卡片里的选择都会被默认值改回去。实测症状：在卡片里把「状态栏」打开，重启 DSH 后它自己变回关。

现在这四个字段不再写默认值：未设 → 用 `ui.json` → 再落到出厂值（`statusbar` 出厂关，v1.9.3 起的口径不变）。配置里真填了值仍然优先，`factory policy < user policy < ui.json < Config fields` 这条顺序不变。

## 投递目标不再以裸 agent 发言

目标会话没活着时，投递会先 resume 一个临时 agent 替它说话。那次 resume 原先没有 `setup`，于是 agent 是**裸**的：不加入任何预设，工具按进程全局层解析，呈现模式退回 native。跑起来的效果是——那一轮的工具面完全不是这个会话平时的样子（实测：从 1 个 `run_code` 变成 61 个，投递结束再变回来，GUI 因此在对话中间弹了一次工具变更提示），而且那一轮**调不到 `run_code`**。

现在会从会话自己的事件流里读出它加入过哪个预设（`agent-preset/selected`），把同一个挂回去再发言；会话从没记过预设、宿主没有预设服务、或挂载被拒，都退回原来的行为并写一行 `deliver_target_preset` 留痕。

## 表述与预算

- 「判『别说』时一个 token 都不花」过宽——闲逛相在闸门之前触发。文档改为「之后的**决策与表达**两相不再调用模型」；
- 账本块与摘要加了长度上限，超预算的条目整条跳过，不再从句子中间切断；
- 闲逛搜索的年份不再写死 2026。

## 工程卫生

- 所有外部输入（模型输出、流水读入、迁移包、RPC 载荷）统一用 schemastery 校验形状，未知字段与缺失必填都被拒；
- 原子写先 `fsync` 再改名；加密临时窗口的崩溃残渣在首次使用时清理；
- CI 增加构建检查、`dist` 一致性检查与浏览器端 `client.js` 语法检查——检查当场发现跟踪的 `dist` 早已过期（npm 会发出与源码不符的包），已重建；
- 新增 38 条回归测试（审查修复部分）。

## 一并带上：v1.9.3 的内容

v1.9.3 改完了但从未单独发版，所以它那批改动会随 2.0.0 一起到用户手上：

- **素材包可以留白**：判断从「挑哪条说」变成「要不要开口」，决定沉默时正文留空，只记一次「这轮没开口」与原因；
- **摘要预算分区**：送进引擎室的画像摘要总预算 3200 → 6000 字符，tact / topic / wander 各有上限，超预算整条跳过；
- **出厂默认更省**：心跳间隔 60 分钟、每日开口上限 10、状态栏默认关闭（已保存的设置不受影响）；
- **节省 token 模式能唤醒**：暂停期间每 3 分钟探一次闸门，绑定会话出现新消息立刻恢复；
- **周报保留期数**：`policy.weekly.keepReports`（默认 3）；
- **设置卡重做**：画像四个分区 + 只读的「引擎室输入」视图、素材池四个按钮（含归档），列表都加了滚动区。
