# v1.9.1 · 2026-10-07

**一次全量代码审查，86 项修复**：没有新功能，也不改用法——改的是代码结构与一批可靠性问题。其中三条最值得知道：心跳卡死有了看门狗兜底、说了话不会再丢账、观察游标换成了不会错位的记法。

## 修复：心跳卡死不再需要重启

某一跳如果卡在模型调用上，插件以前会一直以为自己在跳、之后再也不动，只有重启才好。现在超过 **45 分钟**强制收尾并记 `beat_watchdog`，下一拍照常（**不补跳**）。同一类问题还修了三处：`agents.create/resume` 超时后不再留在后台跑、决策轮等待空闲的超时也会真正取消、心跳 agent 失活时能自愈重建。

## 修复：投递成功就一定落账

投递成功后如果碰上超时或异常，以前会漏记这一笔，连带冷却与每日上限都算错。现在**投递成功无条件落账**，超时的另记一条 `spoke_late`——这是新增的锚点，用来分辨「真的晚了一点」和「根本没送到」。

## 修复：观察游标改用宿主绝对序号

游标以前记的是「第几条事件」，会话一旦被压缩、或事件被重写，游标就会指错地方，表现为漏读或反复重读同一段。现在按宿主的绝对序号记；升级后旧格式游标自动丢弃并全量重扫一遍，会留一条 `cursor_format_discarded`——**看到它一次是正常的**。

## 修复：素材不再「说出口就消失」

聊天素材（画像合并时从对话里挑出的话题）以前被说出口就当场退场，常常话刚说完上下文就断了。现在**至少活到下一次回收**，有新证据还会继续留池。同组还修了「恢复出来的冷板凳素材下一拍又被归档」和「新证据豁免条件恒真、规则退化成按次数算」两个问题。

## 修复：周报的画像写入统计

周报统计「本周画像写了几条」时只读活跃 journal，快照轮转之后这个数字会**静默归零**。现在同时读归档与活跃两份。

## 修复：跨夜浏览窗口

配置里写的跨夜窗口（比如 22:00–02:00）以前判定永远为假——配了等于没配，且毫无提示。现在与静默时段的判定口径一致。

## 改进：画像合并能看到 psy 分区

此前模型看不见 psy 条目，却能往里写；写进去因为没有编号就再也改不动，还可能被重复写入。现在**四个分区的条目字段都进合并视图**（字段范围不变：编号 / 分区 / 主题 / 子主题 / 内容 / 置信度；观察引语仍最多一句，仍不送对话原文）。这是有意放宽原先「psy 不出库」的口径。

## 改进：表达被拦下时留下痕迹

素材包发出去了、目标却没说话时，日志里以前一片沉默。现在记 `expression_dropped`（带丢弃原因），连续三次另记一条 `expression_dropped_streak`。

## 改进：数据通道多了道自检

浏览器端的数据通道依赖宿主提供的门禁（Host / Origin 校验 + 会话 secret）。宿主没提供时，删除 / 迁移 / 改配置这类端点现在**直接拒绝并留痕**（`rpc_host_gate_missing`），只读端点照常——而不是默默裸奔。

## 改进：配置里「写了但没生效」的开关全接上

`config/interests.json` 的 `_schedule`（每日闲逛场次、每场焦点数、每焦点最多几条）和 `config/busy-rules.json` 的四个阈值，以前只有一部分真在读。现在全部读。

## 改进：作息峰值不再被噪声顶掉

「近期活跃时段」现在要同时过两道门（强度阈值 + 相对最高值的占比），指数衰减的残渣也会归零——不会把一次偶发熬夜报成你的作息。

## 改进：焚毁与迁移更稳

- **焚毁清单补全**：v1.9.0 新增的运行时文件（报账、偏好、游标、画像快照、周报、journal 归档）以前不在清单里，现在补齐。
- **迁移改成两阶段**：先全部暂存、再统一切换，中途失败会回滚，不再留下半套记忆。
- **审计写入不再掀翻整轮**：审计落盘失败以前会让整轮画像合并中断，现在只记一条警告。

## 工程卫生

- 补了类型声明（`types` 字段 + 构建产出 `.d.ts`）；
- 清了重复的锁文件（只留 npm），构建统一走 npm 的扁平依赖布局；
- 加了 CI（Windows runner：`npm ci` → 类型检查 → 测试）；
- 新增 47 个回归测试（编排器、RPC 通道、会话绑定），测试总数到 **282**。

## 升级提示

- 不需要迁移任何数据，装上升级即可。
- 首次心跳若出现 `cursor_format_discarded`，那是旧游标被丢弃重扫，正常现象，只会出现一次。
- psy 分区的出库口径有放宽（见上）；如果你不希望 psy 参与画像合并，可在设置里关掉 psy 分区。
- 安装/升级方式不变（npm 或 GitHub release）。
