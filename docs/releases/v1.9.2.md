# v1.9.2 · 2026-10-10

**把用户数据从包目录里搬出来，并修掉一个会让整个 DSH 起不来的预设声明**。这一版没有新功能，两条主线都指向同一件事：升级之后，数据还在，宿主还能起得来。

## 修复：心跳模式预设改为运行时注册

以前心跳模式的预设在包里的 `cordis.patch.yml` 里声明宿主包 `@deepseek-ai/dsh-agent-preset`。这要求 profile 自己能解析到这个包，于是有两种死法：

- **profile 解析不到** → 整个插件树加载失败，DSH 起不来；
- **手工把包补进依赖** → 宿主的装载机制出现两份实例，之后**任何会话都无法恢复**（报 `prompt section "deployment:persona-prefix" is already registered`）。

现在预设定义活在插件自己内部，加载时经宿主 API 运行时注册——由声明方自己提供定义正是这个接口的用途。宿主没有这个接口时只记一条审计日志，绝不让宿主挂掉；老宿主仍走原本的自装路径。

## 修复：会话恢复失败不再无限重试

旧格式会话迁移被拒时属于**永久性失败**，以前和网络抖动一视同仁地退避重试，结果引擎室被反复重试拖住、永远空转。现在这类失败单独识别：当场重建会话并把正身指过去；真正暂时性的错误仍照旧退避。

## 修复：数据目录默认移出包外

默认数据目录以前是包内的 `data/`，而它在 `node_modules` 底下——`dsh plugin add`、`pnpm add`、以及每次升级替换包目录，都会连带删掉画像、素材池与正身记录（原本只有显式 `burn` 才会销毁）。

- 默认位置改为 `<DSH_HOME>/heartbeat-data`（一般是 `~/.dsh/heartbeat-data`），**在包外**，重装 / 升级 / 卸载都不碰。
- 想换位置：插件的 `dataDir` 配置项，或环境变量 `HEARTBEAT_DATA_DIR`。
- **老数据自动搬迁**：v1.9.1 及更早装在包内的 `data/`，升级后首次启动自动搬出去——先备份、再逐文件校验（文件清单、大小、sha256 全部一致），全部通过才删原件与备份；任何一步失败都原地不动并留痕。
- **显式配过 `dataDir` 或 `HEARTBEAT_DATA_DIR` 的一律不搬**——你自己钉过位置，插件不擅自改。

## 升级提示

- 不需要手工迁移任何数据，装上即可；如果你原来用的是默认位置，首次启动会自动搬迁。
- 想确认搬迁结果，看日志里有没有 `data_dir_relocated`（成功）或 `data_dir_relocate_failed`（失败并原地保留）。
- 安装/升级方式不变（npm 或 GitHub release）。
