# v1.7.3

**修复：心跳进行中拖住宿主关闭**

此前桌面端更新若恰逢一跳（心跳循环）正在跑，更新器的优雅收尾会等不到心跳结束而超时中止，报「未能安全停止任务」（Host did not complete graceful task teardown）。

根因：宿主关闭时心跳的定时器会被正常清理，但**已经跑到一半的那一跳不会被中断**——其中最长的模型调用有 240 秒预算，宿主在宽限期内等不到它结束。

## 修复方式

- 一跳启动时注册 agent 取消钩子（复用孤儿轮次的既有 cancel 语义），结束时清除；
- 编排器 disposer 清理定时器后调用该钩子，取消进行中的一跳，宿主的活动任务立即结束；
- 审计日志新增 `orchestrator_disposed` 的 `beatCancelled` 标记，可查证是否发生过关机取消。

## 说明

- 升级后**重启 DSH** 即可，无需手动操作。

安装/升级方式不变（npm 或 GitHub release）。
